# Internationalization module

Status: thin. One flat JSON catalog per locale in `i18n/messages/` (`en.json` is the reference); keys are dotted
(`notes.empty.title`), values use `{name}` placeholders. No plural rules yet: for languages with several plural forms
use one key per form (`notes.count.one`, `notes.count.other`) or add ICU MessageFormat when you need it.

`deno task i18n:check` (also part of `deno task check`) fails when a locale lacks a key, has an extra one, or changes
the placeholders. Add a language by copying `en.json` to `<locale>.json` and translating it.

| Where        | How                                                                                                                          |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| Backend      | `import { t, negotiate } from "../i18n/mod.ts"`; `t(negotiate(c.req.header("accept-language")), "errors.unauthorized")`      |
| Web (React)  | `import messages from "../../../i18n/messages/en.json"` and a small `t()`, or a library such as i18next fed with these files |
| React Native | Same JSON import; read the device locale with `expo-localization`                                                            |
| Flutter      | Generate `.arb` files from the JSON with a short script into `lib/l10n/`, then use `flutter gen-l10n`                        |

Machine translation is a draft, not a result: have a native speaker review user-facing text. Test layouts with long
strings (German) and right-to-left languages before launch.
